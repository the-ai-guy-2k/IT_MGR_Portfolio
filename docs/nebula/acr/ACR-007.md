## 1. Implementation approach

Progressive enhancement. No third-party share libraries, trackers, pixels, cookies, or social SDKs.

- A native `<details>` / `<summary>` control labeled **Share Portfolio** is placed after the overview glance and again in the footer.
- Fallback channel links are real `href` values and work without JavaScript.
- JavaScript feature-detects `navigator.share` and, when present, reveals **Share via this device**.
- Explicit Facebook, LinkedIn, X, Email, and Copy Link options remain available even when native sharing is supported.
- Copy Link writes the canonical production URL, not `localhost`, GitHub, or a Replit workspace/preview URL.

## 2. Share options implemented

| Option | Behavior |
|--------|----------|
| Share via this device | Native Web Share API when `typeof navigator.share === "function"` |
| Facebook | `facebook.com/sharer/sharer.php?u=` canonical URL |
| LinkedIn | `linkedin.com/sharing/share-offsite/?url=` canonical URL |
| X | `twitter.com/intent/tweet?url=` canonical URL and professional title text |
| Email | `mailto:?subject=&body=` with title, existing description, and canonical URL |
| Copy Link | Clipboard API, then `document.execCommand("copy")` fallback |

The visitor remains responsible for completing any social post.

## 3. Native Web Share behavior

Feature detection: `typeof navigator.share === "function"`.

When supported, `navigator.share({ title, text, url })` is called with:

- title: `Sanil D Tison — IT Support & Operations Leader`
- text: existing validated description (Desktop Support / EUC / service delivery / technology operations leadership)
- url: `https://it-management-leadership-portfolio.replit.app/`

Cancellation is ignored. Desktop Chromium used for local validation did **not** expose `navigator.share`; the native button stayed hidden (`data-share-ready="fallback"`). That is correct feature detection.

---

## 4. Fallback behavior

Without native share, the panel still offers Facebook, LinkedIn, X, Email, and Copy Link. Those links are also in the markup if JavaScript is disabled.

Copy confirmation: `Link copied` on success. If the clipboard APIs are blocked (observed in the automation webview), the production URL is shown in the live region so the visitor can still copy it.

Opening Share closes the mobile Menu, and opening Menu closes Share, so the two controls do not overlap.
